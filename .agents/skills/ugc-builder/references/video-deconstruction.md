# Video Deconstruction Reference

Use this when analyzing a reference video before any rebuild decisions.

Canonical source: `guides-and-blueprints/UGC Deconstructor.md`.

## Evidence Sources

- Use frames for visual structure, movement, scene, props, lighting, and gestures.
- Use transcript/captions for exact dialogue, speech rhythm, pauses, and voice clues.
- If using the `watch` skill, cite timestamps from frames/transcript when useful.
- If transcript is missing, analyze visuals and mark dialogue/voice as unavailable.

## Required Analysis

Cover these areas:

- Full script transcription when available.
- Hook frame: what happens in the first 0-2 seconds and why it stops the scroll.
- Camera: shot type, angle, phone/pro camera feel, lens width, stabilization, shake, focus behavior, artifacts.
- Motion: subject motion, camera motion, prop motion, scene motion source, edit rhythm.
- Visual authenticity: framing, lighting, noise, shadows, background realism, environmental proof.
- Environment and props: location, furniture, visible objects, product placement, hand/prop interactions.
- Audio: room tone, background sound, dialogue quality, voice timbre, voice texture, speech markers.
- Subject and performance: appearance, posture, energy, countenance, micro-expressions, blinking, kinesics, hair/clothing/skin physics.

## Beat Extraction

Extract 3-5 major beats by narrative function, not every edit:

- Hook
- Setup
- Main point or payoff
- Product/demo moment if relevant
- Closing or CTA

For each beat, capture:

- approximate timestamp
- narrative function
- frame objective
- key pose/action/expression
- camera/framing
- props and hand positions
- lighting/fidelity cues

## Hybrid Reference Rule

If both a reference video and separate start frame image exist:

- Video controls pacing, camera behavior, edit rhythm, motion, and realism cues.
- Start frame controls only the first 0:00-0:02 composition, wardrobe state, subject continuity, and prop placement.
- After 0:02, follow the video rhythm unless the user asks otherwise.

## Output Checkpoint

After deconstruction, stop and ask what to preserve/replace before drafting final prompts.
